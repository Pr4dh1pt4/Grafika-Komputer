Three.js Interactive 3D Application

Aplikasi 3D interaktif dengan scene graph bertingkat, material PBR, model GLB beranimasi, raycasting untuk hover dan selection, panorama HDR, serta postprocessing bloom.

Deskripsi Praktikum

Praktikum ini melanjutkan scene Three.js pada Praktikum 6 menjadi aplikasi yang dapat dijelajahi dan dipilih objeknya. Model Duck.glb dimuat secara asynchronous dengan GLTFLoader, panorama HDR diproses PMREMGenerator untuk refleksi, dan hasil render melewati EffectComposer agar emisi kuat menghasilkan halo bloom.

02

Cara Menjalankan

Buka praktikum7.html melalui server HTTP, misalnya Live Server di VS Code atau python -m http.server. Jangan membuka file langsung melalui file://, karena ES module, Duck.glb, dan file HDR dapat diblokir oleh kebijakan keamanan browser.

python -m http.server 3400
# lalu buka http://localhost:3400/praktikum7.html

Import map di HTML memetakan "three" dan "three/addons/" ke Three.js versi 0.185.1 di jsDelivr; koneksi internet diperlukan untuk library. Aset GLB dan HDR disimpan lokal di folder assets/. HTML, JavaScript, dan CSS dipisahkan agar mudah dibaca dan dimodifikasi.

03

Panorama, Kaca, Silver, dan Bloom

  • Dropdown Skybox / panorama memilih Studio Small 09, Ladybrand Heritage House (assets/ladybrand_heritage_house_1k.hdr), atau panorama procedural. Pilihan memperbarui latar dan refleksi sesuai toggle masing-masing. Selama pemuatan, panorama sebelumnya tetap tersedia; jika gagal, pilihan kembali ke panorama aktif. Pergantian cepat hanya menerapkan pilihan terakhir.
  • Emissive intensity (0–20, awal 5) mengatur emisi sphere kuning hierarchy dan Sun. Bloom intensity (0–3, awal 0.55) mengatur kekuatan halo; Bloom radius (0–1, awal 0.30) mengatur sebarannya. Nilai tampil dan diterapkan langsung. Bloom tetap menggunakan threshold 3, sehingga emisi rendah dapat tidak menghasilkan halo; highlight HDR lain juga bisa terkena bloom. Point light tidak diubah oleh slider emisi.
  • Reset (R) juga mengembalikan pilihan Studio Small 09 serta ketiga parameter emisi/bloom ke nilai awal.
  • Panorama (P) menyalakan/mematikan latar 360°. Refleksi (E) mengatur scene.environment secara terpisah, sehingga silver tetap reflektif ketika latar dimatikan.
  • Bloom menyalakan/mematikan halo cahaya. Sphere kuning pada hierarchy dan Sun memakai emissive kuning dengan intensitas 5 serta point light. Hover/selection tidak mengganti emisi keduanya.
  • Kubus parent menggunakan MeshPhysicalMaterial, transmission: 0.95, thickness: 1.4, ior: 1.45, dan roughness: 0.08 untuk kaca transparan/refraktif. opacity: 1 disengaja karena transparansi kaca diatur melalui transmission. Shadow kubus dimatikan karena shadow map biasa tidak memodelkan transmisi kaca.
  • Sphere besar di kanan depan menggunakan warna silver, metalness: 1, roughness: 0.08, dan refleksi HDR yang diproses dengan PMREM. Slider gallery tidak mengubah material silver/kaca.
  • Refleksi ini berbasis panorama yang dipilih: objek lokal yang bergerak tidak ikut terpantul. Ini bukan ray tracing atau refleksi dinamis menggunakan CubeCamera.
  • Reset (R) mengaktifkan kembali panorama, refleksi, dan bloom, serta membersihkan highlight/scale interaksi.

Rekomendasi format panorama

FormatKapan digunakan
Equirectangular / spherical HDR (dipakai)Satu gambar 2:1 untuk latar 360° dan pencahayaan/refleksi PBR; mudah dimuat dan diganti. HDR menyimpan rentang intensitas cahaya yang lebih besar daripada PNG/JPG.
Cubemap / skybox enam sisiCocok jika aset sudah tersedia sebagai enam gambar px, nx, py, ny, pz, nz; perlu memastikan orientasi dan sambungan antarsisi.

Skybox adalah cara menampilkan lingkungan, sedangkan cubemap dan equirectangular adalah format pemetaannya. Equirectangular juga dapat menjadi latar skybox di Three.js.

Aset lokal: assets/studio_small_09_1k.hdr (sekitar 1.54 MiB), Studio Small 09 oleh Sergej Majboroda, dari Poly Haven, lisensi CC0. Pilihan studio memberi pola softbox yang jelas pada silver dan kaca. Resolusi 1K ringan untuk praktikum; gunakan 2K/4K jika detail latar lebih penting. Lihat assets/README.md untuk sumber unduhan.

HDRLoader memuat aset lokal; PMREMGenerator menyiapkan refleksi sesuai roughness. Jika HDR gagal dimuat, panorama procedural tetap tersedia dan panel menampilkan status fallback. Rangkaian postprocessing: RenderPass -> UnrealBloomPass -> OutputPass, dengan ACES tone mapping. Bloom memakai threshold 3 untuk terutama menangkap emisi HDR; highlight HDR lain yang sangat terang juga dapat berpendar.

Referensi: HDRLoader, PMREMGenerator, OutputPass.

06

OrbitControls — Navigasi dan Selection

OrbitControls dipakai untuk menjelajahi scene dan model GLB. Drag kiri melakukan orbit kamera, scroll mengatur zoom, dan drag kanan melakukan pan. Klik kiri tanpa drag memilih objek dan memperbarui panel informasi. Slider Orbit speed mengatur animasi hierarchy tata surya dan lampu; navigasi kamera memakai mouse.

Kontrol diimpor dari three/addons/controls/OrbitControls.js, menggunakan kamera aktif dan renderer.domElement, dengan target awal (0, 1, 0). enableDamping = true memperhalus gerakan; controls.update() dipanggil sebelum composer.render() pada setiap frame.

PengaturanNilai dan fungsi
minDistance / maxDistance3 / 25, batas jarak PerspectiveCamera dari target
minZoom / maxZoom0.5 / 3, batas zoom OrthographicCamera
maxPolarAngleMath.PI / 2 - 0.05, batas orbit mendekati 90 derajat

Batas polar berlaku terhadap target; pan masih dapat menggeser target sehingga pengaturan ini tidak menjamin posisi kamera selalu di atas ground.

Pergantian kamera mempertahankan posisi dan target, membuat ulang OrbitControls, dan memperbarui renderPass.camera. Reset (R) mengembalikan PerspectiveCamera ke (7.5, 5.2, 9.5), target awal, FOV 52, dan zoom 1.

Untuk mencegah selection setelah orbit/pan, posisi pointer dicatat sejak pointerdown. Gerakan lebih dari 5 piksel dianggap drag, termasuk ketika pointer kembali ke titik awal. Event click setelah drag diabaikan; hover ditangguhkan selama pointer ditekan. pointercancel membatalkan gesture dan klik berikutnya dapat digunakan kembali untuk selection.

Coba: klik objek untuk memilih, drag melewati objek lain, lalu pastikan selection tetap sama. Uji zoom pada kedua mode kamera dan tekan R untuk mengembalikan tampilan awal.

07

Komponen Teknis yang Diimplementasikan

Scene dan renderer

Scene, PerspectiveCamera, OrthographicCamera, WebGLRenderer, resize responsif, HemisphereLight, DirectionalLight, PointLight, ground, shadow map, dan animation loop tersedia pada js/praktikum7.js. Frame time berasal dari THREE.Clock.getDelta() sehingga rotasi tidak bergantung pada jumlah frame.

Scene graph dan local/world transform

hierarchyGroup berisi parentMesh dan childMesh. Child memakai posisi lokal (1, 0.9, 0) dan mengikuti rotasi parent. Panel selection menampilkan posisi lokal dan hasil getWorldPosition(). Karena:

childWorldMatrix = parentWorldMatrix × childLocalMatrix

posisi lokal child tidak berubah ketika parent dirotasi, tetapi posisi world child berubah.

Challenge D memakai hierarchy lain:

Solar System
└── Earth Orbit
    └── Earth
        └── Moon Orbit
            └── Moon

Orbit dihitung oleh transform parent, bukan dengan menghitung semua world position secara manual.

PBR material dan gallery

Prototype menggunakan MeshStandardMaterial dengan roughness dan metalness. Gallery berisi kombinasi tiga tingkat roughness dan tiga tingkat metalness, ditambah satu sphere besar yang mengikuti slider sehingga parameter dapat diuji secara langsung. Challenge E terpenuhi melalui gallery ini.

GLB, hierarchy, texture, dan animation

GLTFLoader memuat Duck.glb secara asynchronous. Setelah berhasil dimuat, gltf.scene diberi transform, setiap descendant diperiksa dengan traverse(), dan seluruh mesh diberi castShadow serta receiveShadow. Panel HUD menampilkan jumlah clip. Jika tersedia clip, AnimationMixer, clipAction(), fadeIn(), fadeOut(), play(), dan mixer.update(delta) digunakan. Jika asset tidak menyediakan clip, prototype membuat tiga clip demonstrasi (Idle, Walk, Run) pada root model agar pergantian action tetap dapat dipelajari tanpa mengubah file GLB.

Challenge A dan B tersedia melalui tombol/keyboard pemilih clip dan click pada model. Clip fallback hanya memutar root untuk demonstrasi konsep AnimationMixer; asset karakter dengan animasi tulang tetap disarankan untuk hasil produksi.

Raycasting, pointer NDC, hover, dan click

Koordinat pointer dikonversi ke NDC:

pointer.x = ((clientX - rect.left) / rect.width) * 2 - 1;
pointer.y = -((clientY - rect.top) / rect.height) * 2 + 1;
raycaster.setFromCamera(pointer, activeCamera);
raycaster.intersectObjects(interactiveObjects, true);

Argumen true penting karena mesh GLB sering berada sebagai descendant dari root model. objectRoot() mengembalikan root interaktif agar child mesh tidak menghasilkan selection terpisah. Hover state bersifat sementara, sedangkan selected state bersifat persisten. Ini memenuhi eksperimen recursive raycast, hover vs click, pointer coordinate, dan feedback visual.

Challenge F menyimpan warna emissive asli pada material.userData.originalEmissive, lalu memberi highlight warm amber (#d88945) saat hover, sehingga material tidak diubah secara destruktif. Challenge G memutar object terpilih berbasis delta time. Challenge C menampilkan name, local/world position, rotation, scale, dan material type pada selection information panel.

Environment dan Bloom

Prototype memuat panorama HDR lokal untuk background dan environment; CanvasTexture menjadi fallback jika pemuatan gagal. Challenge H dapat diuji dengan tombol Environment (E). Saat OFF, material PBR kehilangan kontribusi refleksi environment sehingga perbedaan material metal lebih mudah diamati.

Rendering menggunakan EffectComposer, RenderPass, UnrealBloomPass, dan OutputPass. Bloom aktif secara permanen pada emisi sphere kuning dan dapat di-toggle melalui panel. Hover memberi highlight pada material lain tanpa memadamkan emisi sphere kuning.

GLB Bertekstur yang Digunakan

File Duck.glb disertakan langsung di folder assets/. Sumbernya adalah sample asset resmi Khronos:

https://github.com/KhronosGroup/glTF-Sample-Assets/tree/main/Models/Duck

URL unduhan yang dipakai:

https://raw.githubusercontent.com/KhronosGroup/glTF-Sample-Assets/main/Models/Duck/glTF-Binary/Duck.glb

GLB cocok untuk distribusi offline karena mesh, buffer, dan texture yang dibutuhkan dapat dikemas ke dalam satu binary container. Tetap sertakan atribusi/license dari direktori asset ketika output dipublikasikan. Jika dosen memberikan model lain, ganti Duck.glb dengan file GLB tersebut dan pertahankan nama file atau ubah MODEL_URL pada js/praktikum7.js.
